# مؤجّل قبل/بعد التجربة الحية

وثيقة عودة لاحقة — لا تُنفَّذ تلقائيًا إلا بطلب صريح.

## تصميم MTFH المقترح: أب هرمي لكل فريم (مؤجّل / متزامن مع التجربة)

### الفكرة المتفق عليها للنقاش
لكل فريم مفعّل قائمة منسدلة:

| الخيار | المعنى |
|---|---|
| `off` | بدون فلتر هرمي لهذا الفريم |
| `4h` | الدخول فقط إذا كان فريم 4h داعمًا |
| `1d` | الدخول فقط إذا كان فريم 1d داعمًا |

### قواعد
- الربط يكون **من الأصغر إلى الأكبر فقط** (ابن → أب/جد). لا يُسمح أن يرتبط 4h بـ 15m مثلًا.
- الفريم الأعلى نفسه (`4h`/`1d`) إما `off` أو يرتبط بما فوقه إن وُجد (مثلًا 4h→1d فقط).
- تعطيل الفريم الأب في قائمة التداول لا يمنع استخدامه كمرجع تأكيد إذا اختير في القائمة (يُجلب للفلتر فقط).
- MTF الحالي يبقى بلا هذا الخيار؛ الخيار لـ **MTFH فقط**.

### مثال إعداد أسبوعي
- 5m → `4h`
- 15m → `4h`
- 30m → `4h`
- 1h → `1d`
- 4h → `1d` أو `off`
- 1d → `off`

### حالة التنفيذ
- **لم يُنفَّذ بعد** — مناسب بعد التجربة أو بالتوازي أثناء الأسبوع الحي عند الطلب (`نفّذ هرم MTFH لكل فريم`).

## مؤجّل من قائمة ما قبل التجربة

1. **قائمة تحقق تشغيل أسبوعية**  
   رموز قليلة، أحجام صغيرة، بوت واحد/اثنين، بدون ازدواجية رموز بين MTF و MTFH و X.

3. **سياسة عدم ازدواجية التعرض**  
   عملة لكل بوت أو سقف مشترك على مستوى الحساب.

4. **مراجعة يومية منظمة**  
   قالب تقرير نهاية اليوم (صفقات / عمولة / أسباب إغلاق / تنبيهات).

5. **وضع Paper / Dry-run**  
   إشارات بدون أوامر حقيقية.

8. **نسخ احتياطي روتيني لـ `/data/bot_data.db`**  
   قبل البداية وبعد كل يوم تجربة.

## فكرة واجهة الأداء (Charts / Ops Console)

### الفكرة (كما فُهمت)
- فصل **التشغيل اليومي** عن **الأدوات النادرة + التحليل**.
- الصفحة الحالية `analytics.html` (المسماة «يدوي») مرشحة لتصبح **لوحة عمليات/أداء**:
  - أوامر يدوية نادرة
  - سجلات المنصة
  - شارتات أداء الحساب والبوتات
- بديل: صفحة جديدة `performance.html` والإبقاء على «يدوي» للأوامر فقط.

### تسمية مقترحة
- **لوحة الأداء** / **Performance**
- أو **غرفة العمليات** / **Ops Console** (إن بقيت الأدوات اليدوية معها)

### شارتات مقترحة للأسبوع الحي

**حساب (Account)**
- منحنى صافي الربح التراكمي اليومي (من `closed_trades`)
- PnL يومي (أعمدة)
- توزيع أسباب الإغلاق (TP / SL / TS / BE / EWO / يدوي)
- إجمالي العمولات اليومية

**لكل بوت**
- منحنى صافي البوت
- Win rate عبر الأيام
- متوسط الربح/الخسارة لكل صفقة
- استخدام رأس المال المفتوح (اختياري)
- لـ MTF/MTFH: توزيع الصفقات حسب الفريم

**لاحقاً (اختياري)**
- مقارنة MTF vs MTFH
- Heatmap ساعة الدخول
- Drawdown تقريبي من الصفقات المغلقة

### متطلب بيانات
- الاعتماد على جدول `closed_trades` (دائم في SQLite)
- عدم الاعتماد على `recent_logs` (ذاكرة فقط، آخر ~250 سطر)

## ملاحظات تقنية مفيدة

- `daily_pnl` في الواجهة يُصفَّر عند تغيّر يوم UTC — هذا متوقع وليس مسحًا من القاعدة.
- الصفقات المغلقة تُحفظ في `closed_trades` ولا تُحذف تلقائيًا بالكود الحالي.
- واجهة السجل المغلق كانت تعرض حدًا افتراضيًا (70) — رُفع طلب العرض إلى 200؛ التصدير CSV حتى 2000.
